# План переосмысления — fairytale-wanderings

## Цель

Убрать трение «напиши в личку и перечисли заказ руками». Клиент собирает заказ сам — на сайте или в Telegram-боте — заказ уходит владелице магазина на почту и сохраняется в БД. Онлайн-оплата закладывается как модуль на будущее (СБП/ЮKassa через статус самозанятого).

## Итоговая архитектура

- Клиент: Vue 3 + Pinia + Tailwind (как сейчас).
- Сервер: Hono на Bun.
- БД: **PostgreSQL + Drizzle ORM** (миграция с MongoDB/Mongoose).
- Деплой: docker-compose в облако (VPS ~500 ₽/мес).
- Два канала заказа:
  - **Сайт** → гостевой заказ (без регистрации) → email + запись в БД.
  - **Telegram-бот** → для пользователей с VPN → email + запись в БД.

## Ключевые решения

- **Регистрации на сайте нет** — гостевой checkout. Цель проекта — снижать трение, а обязательная регистрация его добавляет. Контакты клиента пишутся прямо в заказ.
- Таблица `users` нужна **только для бота** (там идентификация — сам Telegram). У веб-заказов `user_id = null`.
- **Корзина — только на клиенте** (Pinia). В БД пишется только готовый заказ; таблицы `cart_items` нет.
- Все зависимости обновляем до последних версий.

- Сменить пароль БД.
- Убрать `server/.env` из репозитория (добавить в `.gitignore`), почистить git-историю.

## Этап 1. Миграция Mongo → PostgreSQL + Drizzle

Таблицы:

- `products` — `id`, `name`, `price` (numeric), `description`, `category`, `images` (jsonb), `details` (jsonb), `is_active` (bool).
- `users` (только бот) — `id`, `telegram_id` (unique), `first_name`, `last_name`, `username`, `phone`, `is_admin`, `registered_at`.
- `orders` — `id`, `customer_name`, `contact`, `delivery_method`, `delivery_address`, `comment`, `total_price`, `status` (enum: pending/processing/shipped/delivered/cancelled), `payment_method`, `channel` (enum: web/telegram), `user_id` (nullable FK → users), `created_at`, `updated_at`.
- `order_items` — `id`, `order_id` (FK → orders), `product_id` (FK → products), `quantity`, `price` (фиксируем цену на момент заказа).

Переписать под Drizzle:

- `DatabaseSingleton` → пул `pg` + инстанс drizzle.
- Сервисы `Product.service` / `Order.service` / `User.service`.
- `filterMiddleware` + `Filter` (Mongo `$regex` → Postgres `ilike`).
- Подключить `drizzle-kit` для миграций.
- В `compose.yml` сервис `mongodb` → `postgres`.

## Этап 2. Рабочий приём заказа + email (сайт)

- Состыковать `client/src/scripts/Order.ts` / `MakeOrder` ↔ роут `/orders/create` (JSON вместо `form`).
- Расширить тело заказа: имя, контакт, способ доставки, адрес, комментарий.
- `OrderService.createOrder`: заказ + позиции в транзакции, сумма считается на сервере по ценам из БД, проставляется `channel`.
- Email-уведомление владелице через SMTP (Yandex / Mail.ru — работает из РФ без VPN, `nodemailer`). Креды в `.env`. Шаблон письма: состав, суммы, контакт, доставка.

## Этап 3. Telegram-бот как второй канал

Сейчас бот умеет только регистрацию (`/start` + телефон); сам заказ не реализован (`chooseProduct.ts` пустой), запуск закомментирован.

- Дописать: каталог из БД → выбор товара/количества → корзина → оформление.
- Заказ через тот же `OrderService` (`channel=telegram`, `user_id` из регистрации) → то же письмо на почту.
- Включить запуск бота в `index.ts`.

## Этап 4. Фронт: форма гостевого заказа

- `CartView` → шаг оформления: имя, контакт (телефон/почта), способ доставки, адрес, комментарий.
- Отправка JSON на `/orders/create`, экран «заказ принят».
- Без регистрации.

## Этап 5. Слот под оплату (задел, без реализации)

- Поля `status` / `payment_method` в `orders` оставляем как точку расширения.
- После оформления — место под кнопку «Оплатить» (СБП/ЮKassa), включится после оформления самозанятости.
- Пока — «оплата по договорённости».

## Этап 6. Деплой и безопасность

- Postgres не публиковать портом наружу (только внутренняя docker-сеть).
- Все креды через `.env`.
- Домен + SSL (Caddy или nginx).
