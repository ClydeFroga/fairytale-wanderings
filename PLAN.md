# План — fairytale-wanderings

Магазин подруги: каталог + заказы. Цель — убрать трение «напиши в личку и перечисли заказ руками»: клиент собирает заказ сам (сайт — гостевой checkout; Telegram-бот — для пользователей с VPN), заказ уходит владелице и сохраняется в БД.

Стек: Vue 3 (клиент) + Hono/Bun + PostgreSQL/Drizzle (сервер), docker-compose. Подробности по серверу — в `server/CLAUDE.md`.

## Готово ✅

- **Зависимости** обновлены до последних (Vue 3.5, Vite 8, ESLint 10, Hono 4.12, zod 4, TS 6 и т.д.). Mongoose оставлен на 8.x и затем убран при миграции.
- **Этап 1 — миграция БД Mongo → PostgreSQL + Drizzle.** Схема по файлам в `server/src/global/database/shema/` (products, users, orders, order_items + enum-ы). Пул и drizzle — в `DatabaseSingleton` (экспортирует `db`). Миграции через drizzle-kit (`server/drizzle/`). Compose переведён на postgres (порт на хосте — **15432**, наружу через `POSTGRES_PORT`).
- **Этап 2 (часть) — запись заказа в БД.** У товара есть `stock`; при заказе остаток списывается атомарно (`stock >= qty`), при нехватке — `InsufficientStockError` (409), нет товара — `ProductNotFoundError` (404). Цена фиксируется из БД. Сохраняются имя и контакт. Гостевой checkout (без регистрации), `userId = null`.
- **Структура и конвенции** (см. `server/CLAUDE.md`): бизнес-логика — в роутах; `database/methods/` — только обращения к БД (импортируют `db` напрямую); ошибки — в `global/errors/` (`AppError` + наследники со `status`); единый обработчик — `middleware/errorHandler.ts` через `app.onError`. Роуты разложены по папкам (`routes/<name>/route.ts|validator.ts|helpers.ts`).
- **Seed**: 5 тестовых товаров с остатками (`bun run db:seed`).

## Осталось

### Этап 2 (завершить) — уведомление о заказе на почту
- Отправка письма владелице при создании заказа через SMTP (Yandex/Mail.ru — из РФ без VPN, `nodemailer`). Креды в `.env`. Шаблон: состав, суммы, контакт, доставка.
- Письмо слать после успешной записи заказа (в роуте `routes/orders/route.ts`).

### Этап 3 — Telegram-бот как второй канал (для VPN)
- Сейчас бот умеет только регистрацию (`/start` + телефон); запуск в `index.ts` закомментирован, `chooseProduct` — заготовка.
- Дописать: каталог из БД → выбор товара/кол-ва → корзина → оформление → тот же заказ в БД (`channel=telegram`, `userId` из регистрации) + то же письмо.

### Этап 4 — фронт: форма гостевого заказа
- `CartView` → шаг оформления (имя, контакт, доставка, адрес, комментарий) → POST `/orders/create` (JSON) → экран «заказ принят».

### Этап 5 (в самом конце) — доставка и оплата
Подключаем после того, как базовый магазин (сайт + почта) работает.
- **Доставка:**
  - **СДЭК** — виджет `cdek-it/widget` (карта ПВЗ + расчёт стоимости) + бэкенд-прокси к CDEK API v2 (`routes/cdek/`, OAuth-токен на сервере). Нужны: аккаунт интеграции СДЭК (есть тестовые креды), вес/габариты (для старта — дефолтная упаковка), город-отправитель.
  - **Почта России** — API расчёта тарифа и/или поиска отделений (по аналогии с СДЭК — серверный прокси, креды на сервере).
  - В заказ добавить: способ доставки, выбранный ПВЗ/отделение, стоимость доставки.
- **Оплата** — сервис пока **не выбран** (кандидаты под самозанятость: ЮKassa / Робокасса / Продамус / ЮMoney, приём по СБП-QR с низкой комиссией). Поля `status`/`paymentMethod` в `orders` уже есть как точка расширения. Требует у владелицы статуса самозанятого + договора с платёжным сервисом.
